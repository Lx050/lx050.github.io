# WORLD SCALE BRIEF — 夜游数字庭院 · 宏伟化改造（第一波 / Wave 1）

> 执行者：GPT-6（Codex）。本文件是**唯一规格**。在满足全部硬约束与验收标准的前提下，
> 具体数值、布局、算法由你自行判断与权衡，不必请示。先通读 `index.html` 全文再动手。

## 0. 一句话目标
现在它是一个"低头看的盆景圆盘"（岛半径 31、建筑只有 3–4m 高、相机在 50m 高空 45° 俯视）。
要把它变成一个**需要仰望、可以走远、走进去有纵深的宏伟夜世界**——但本轮**不新建任何模型、不加外部依赖**，
仅用现有 34 个 GLB + 程序化几何，通过**尺度重标定、人视相机、参道基座、垂直高差、远景借景、性能分级**实现。

美学纲领：**素体万彩、写意不取形、纪念碑性、可动即语义、装饰即叙事、一作一世界。**
气质 = 宏伟到需要仰望的建筑，脚下守着一盏温暖的小灯（提灯人 1.7m 是永恒的人体尺度标尺）。

## 1. 尺度重标定（1 单位 = 1 米，提灯人 = 1.7m，不得改变人物大小）
在代码顶部建立集中、可调的 `WORLD` 常量（替换现在散落的魔数 31.5 / 33 / 30 / 360 / .0085 等）：
- `PLAYER_HEIGHT = 1.7`（人物几何现状即约 1.7m，**保持**，它是标尺）。
- 大陆可走半径 `ISLAND_RADIUS ≈ 150`（原 31.5）。地形圆柱/崖锥/水岸/岸缘/接触阴影/树环/星点/粒子范围全部按此重算。
- 26 个条目重排到更大的世界：按现有 4 个 zone（作品/服务/项目/连接）分成**四境扇区**，
  条目沿 1–2 条环带（建议半径 60 / 95–120）确定性分布（**用固定种子或公式，不要每帧随机、不要重叠**）；
  同一扇区内相邻地标间距 ≥ 24m；每个地标独占一个圆形台地（半径 9–15m）。
- `LINKS` 的 `zone/title/desc/url` **一字不改**；只重新计算/提供 `x,z`（可由布局函数生成，保留数据可读性）。

### 1.1 地标必须真正宏伟（核心）
- 现状 GLB 以 `scale=1` 放置，只有几米高。改为写一个 `placeMonument(glb, group, {targetHeight, tier})`：
  加载后读取模型**世界包围盒高度**，按"目标高度"等比归一缩放并使**底部精确接地**（y=台地面），x/z 居中。
- 目标高度分级（L2 纪念碑尺度，单位米）：
  - 普通条目主体 **30–42m**；
  - 重点条目（建议 Vault(LM10)、Patent(LM08)、Butterfly(LM24)、Konigsberg(LM27)、MindCare(LM25)、Gateway(LM11)）**48–70m**；
  - 允许你按模型实际形态微调，但**任何地标主体不得低于 24m**。
- 程序化 fallback 几何（GLB 加载失败时的 zproc）也要按同等级放大，不能失败时缩回 3m 小房子。

### 1.2 没有"小"就没有"大"——人体尺度参照物（必须逐座配置）
每座地标台地必须包含真实人体尺度的物件，用来标定宏伟：
- 台地前沿一对 **2.4m 高石灯笼**；一道**真台阶**（每级高 0.15m、深 0.4m，3–6m 总高）从主步道抬升到基座平台；
- 基座平台、宽约 3m 的参道；参道两侧每 ~6m 一盏灯或一棵**真实尺度 5–8m 的树**（树不得跟着放大成巨物）。
- 门/入口构件按 2.2–3m 真实尺度。让玩家站在脚下时，建筑明显高出自己 20–40 倍。

### 1.3 参道与序章（收—放节奏）
- 每条参道长 15–30m，由主环步道分叉通向台地；两侧低柱/灯/树形成"窄而收"的引导，
  登上台阶到达平台后"豁然"面对宏伟主体。
- 中央庭心（玩家出生点）保留为开阔、低建筑的"放"，四境向外逐渐宏伟；最外圈以远景收束。

## 2. 相机人视化（宏伟感的第一功臣，优先级最高）
现状 `PerspectiveCamera(45,…,.5,360)`、开场在 (32,~50,~51) 高空、游戏中 distance 26–30 / pitch .78（45°俯视）。
- `far ≥ 2200`；`near .4`；FOV 收到 **38–42**。
- **开场（未 started）**：禁止高空俯视。机位降到人视（相机 y 在 1.8–4m 之间），
  放在南侧鸟居（Torii）外的参道上，透过放大到约 12–14m 的鸟居望见庭心与远处发光地标群（建立纵深与宏伟）；
  可极缓慢推进/轻微环绕，但始终是人视低角度。
- **游戏中第三人称**：目标点 `target y ≈ 1.6`；默认 `distance ≈ 6.5`（拖动/滚轮可在 4–12 间调，移动端给合理默认）；
  默认 `pitch ≈ 0.2`（约 11°，接近平视）；**pitch 上限 0.62（约 35°），禁止再到 0.78 的俯视**，下限允许到约 −0.5（仰拍）。
- **靠近地标自动仰拍 framing**：当 `nearest` 且玩家在台地参道/平台一定范围内、且玩家未拖动视角时，
  平滑把目标点抬向建筑高度的 0.3–0.55、pitch 向负值过渡形成仰望，并让建筑居于画面；离开后平滑回正。
  不要突兀、不要夺走控制权（用户拖动时立即让位，沿用现有 lookActive 思路）。
- 玩家拖动环顾/键盘转向/移动端 viewpad 与摇杆全部继续可用；转向速度按新 distance 重新调到舒服。

## 3. 垂直、地貌与借景
- 大陆不再是平圆盘：用确定性高度函数给地形**起伏**（缓丘、坡地、台地抬升、临海岸崖），
  台地/基座随地形抬高；保证步道与参道始终可走（walkable 与视觉地面一致，不能出现看得见走不上去的坎）。
- **远景借景**：在半径约 300–750m 放一圈**低模远山/远洲剪影**（cone/自定义轮廓，`MeshBasicMaterial` 取雾色、
  不投影、不碰撞、不吃实时光照），让世界望不到尽头；远处地标与群岛在雾中若隐若现。
- 月亮/天穹尺度与位置配合新世界，保证仰望时有天。
- 数学三岛（柯尼斯堡/叙拉古/图卢兹）与七桥机制**保留**；随大尺度等比外移/放大，确保桥仍连接可走、
  walkable/登岛/计数/欧拉卡/Euler `__garden` 全部仍成立。若把它们做成"远眺 + 长桥可达"的远境更合适，可自行判断，
  但七桥玩法不能丢。

## 4. 雾、光照与阴影随尺度修正
- `FogExp2` 密度调稀到约 `0.0016–0.0028`（使 100–200m 外才渐隐，配合远山），昼夜循环 `skyTick` 里的密度同步重标定。
- 方向光（moon/sun）阴影相机现状固定 ±37，世界放大后只会照亮玩家身边一小块：
  改为**阴影视锥跟随玩家**（每帧以玩家为中心定位 light.position/target，覆盖半径桌面 ~70、移动 ~40），
  mapSize 桌面 2048、移动 1024；保证玩家周边建筑/台阶有正确实时阴影，远处靠假阴影/烘焙感。
- 地标放大后，其 emissive/光晕/标签高度要随之重定位：名称 sprite 位于新的建筑顶部之上，
  beacon/halo 尺寸按新尺度；`name` 显隐距离阈值（现 28）按新世界调（如 90）。

## 5. 性能与分级（宏伟不能以卡顿为代价）
- 台阶/灯柱/树/栏杆/卵石等**重复件一律 InstancedMesh / 共享 Geometry+Material**，控制 draw call。
- 远景剪影、远洲不进 shadow pass、不用标准材质。
- 沿用并扩展现有 `lightQuality / qualityReduced / reduceQuality()` 与持续慢帧自动降级：
  移动端/低性能：像素比上限更低、阴影跟随半径更小或关闭、远景剪影数量减半、bloom 关闭策略不变、
  必要时对远处地标用简化剪影/更低 LOD（你可实现按距离切换：远则低模/imposter，近则 GLB）。
- 目标：桌面稳定 60fps（不触发自动降级），中端手机（390×844 模拟）≥ 30fps 可漫游；
  首屏体积不得因本轮显著膨胀（不新增大资源，复用现有 GLB/vendor）。

## 9. 验收标准（自动 + 人工，全部必须满足）
- A1 控制台 **0 error**（GLB 缺失类 warn 可接受，但现有 34 个 GLB 都应成功加载）。

- A5 出生点与每个地标台地、参道、桥、三岛在 `walkable()` 中均可站立/可达（用 `__garden.teleport` 逐点验证）。
