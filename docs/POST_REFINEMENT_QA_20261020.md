## 当前 CPU 验收命令

在包含完整 Git 历史的仓库中运行：

```sh
node docs/current-release-check.cjs
```

结果写入 `qa-results/current-release/report.json`。此命令显式区分：

1. **当前源码**：所有运行时资产逐字节对照上一版，仅允许上述东线代码和两入口对应缓存版本；拒绝任何其他生产变动。校验发布哈希、缓存版本和精确差异的反例。
2. **当前几何与逻辑**：31 项仍适用的原有 CPU 检查，加上 Wave1 源码契约反例与新的东线实际装配检查。当前几何不经过历史还原。新检查检验导引线连续性、身体净空、中央通道，以及文字、阅读台、碰撞体、西线和其他构件保全。
3. **历史固定样本**：65 项旧版 CPU 检查在隔离的、固定到上述基线的临时仓库运行。只修复两个无法从远端取得的历史基线引用，不改变任何原等式断言。这些结果明确标为 `historical-fixture`，不能冒称新版 WebGL 或新版整体几何验收。

`--current-only` 仅用于快速检查，报告 `complete: false`，不是上述完整 CPU 验收。

2026-10-20 最终执行结果：33/33 项当前检查与 65/65 项历史固定样本检查通过，聚合报告 `passed: true`、`complete: true`。132 个运行时资产、78 项发布哈希、225 个 HTML 缓存引用核验通过。东线检查完成 24 次保全快照对比、12 组实际几何净空验证及 6 个失败反例；116 个碰撞体保持。此结论仍只限上述 CPU 范围。

34 项旧脚本固定了各自发布时的整文件、实例数组或累计数量，直接在已修正东线的新源码上运行会触发旧版不变量。它们被保留为历史样本，未批量放宽；新聚合检查负责当前版本的严格差异和几何覆盖。除上述两个准确基线引用外，65 项旧检查的源码也逐字节保全。

## 修复验收工具的历史问题

- Wave1 的固定 `LINKS` 哈希早于 13、14、15、19、20 号入口改为站内阅读。现逐项强制验证五个准确的 `/?read=N`，仅还原这五个已验证 token 后比较旧哈希；其他文字、坐标、URL 和音乐字节仍须符合原契约。37 个反例验证意外变化必然失败。
- `node docs/wave1-check.cjs --source-only` 无须加载浏览器依赖。完整历史浏览器入口会分别报告源码、浏览器启动、运行时就绪或旧建筑契约不适用，不再把这些阶段混成一个失败。
- Wave1 后续的 34 GLB、24 m 以上纪念碑等阈值属于旧建筑版本，未降低阈值，也未宣称适用于当前可进入建筑。
- 排版馆基线修复为其精修提交的确切已发布父提交 `386c2b123a5a30e785714aec22a354f998af03d9`；暖聆 App 修复为 `9f2743e5e095da869a5594e8c266fe3de7709c76`。两者都与原设计记录吻合。修复后、东线改动前的 66 项 CPU 检查全部通过。
